# Product documentation

Documentation is a separate **文档管理** administration module. Create products in **品牌与产品** first, then choose a product in the document manager. Product creation has four steps: basic information, overview, installers and publishing. Store policies stay under system settings.

Each product has an ordered library of custom groups and articles. Administrators and operations staff can create, rename, delete, reorder and move articles between groups. Nonempty groups must be emptied before deletion. Dragging and keyboard-accessible menu actions are both supported.

The editor supports headings, emphasis, links, uploaded images, lists, code blocks and tables. It automatically saves drafts. Publishing copies the complete article, including its SEO, into a separate published snapshot. Editing a published article leaves the current public version intact. Unpublishing removes it from public navigation and the sitemap.

## SEO belongs to each article

Open an article and select **SEO 与分享**. The title, description, share image, indexing choice and optional custom URL belong to that article, not its product. Empty titles/descriptions use the article's title/body. Product-page SEO does not override an article's indexing choice.

URLs are generated automatically and do not change when an article is renamed. The advanced URL setting is optional. Publishing a changed URL preserves a permanent redirect from the old published URL. Historical URLs cannot be reused by other articles.

Public URLs use the existing locale routes, for example `/zh-cn/products/test-editor/docs/article-…`. They serve the actual article body, title, description, canonical URL and social metadata in server-rendered HTML. Only published articles of published products are publicly accessible. Drafts and previews are private; `noindex` articles are omitted from the sitemap. Article translations are not generated by this module; untranslated locale copies are marked `noindex`.

## Persistence and API

`document_libraries` stores a versioned, ordered library per product with independent draft/published article copies. It is included in the existing model-based encrypted backups. No old product text fields are migrated into the new library.

- `GET /api/v1/admin/documents/{product}` reads the staff library.
- `POST /api/v1/admin/documents/{product}` applies a command with the current `version`.
- Commands: `create_group`, `rename_group`, `delete_group`, `move_group`, `create_article`, `save_article`, `publish_article`, `unpublish_article`, `move_article`, `delete_article`.
- Conflicting revisions return HTTP 409; one editor cannot silently replace another editor's changes.
- Mutations use the existing authentication, CSRF and audit mechanisms. Public site projections contain published snapshots only.

## Verification

Unit tests cover Markdown safety, snapshot privacy, reorder/move behavior and URL reservation. The isolated HTTP integration test creates its own `launch_test_documents_*` database and tests permissions, revision conflicts, product isolation, SSR, redirects, independent article SEO, indexing and the sitemap. It never initializes or changes the database named in its base DSN.

Set `LAUNCH_DOCUMENT_TEST_BASE_DSN` to a server account allowed to create a temporary database and run `go test ./internal/httpapi -run TestDocumentManagementHTTPAndSEO -count=1`. The test drops its temporary database by default. `LAUNCH_DOCUMENT_PREVIEW_CONFIG` is an optional private fixture destination for local UI verification.
