# Configuration reference

Launch stores private startup settings in **`config.yaml`**. Run `launch init` to generate it with an independent persistent master key, edit `database_dsn`, then run `launch serve`.

## Loading configuration

- `launch serve`, `dev`, `check`, `backup`, and `restore` automatically read `config.yaml` from the working directory.
- Select another file with `launch serve --config /etc/licentivo-launch/config.yaml`. `--config` takes precedence over the `LAUNCH_CONFIG_FILE` environment variable.
- With no explicit selector, the program reads `config.yaml` in the working directory. An invalid selected file causes an error.
- Nonempty `LAUNCH_*` process environment values override the corresponding values in the selected file. Built-in defaults apply last.
- YAML accepts the string keys below, rejects duplicate/unknown keys and multiple documents, and supports comments. Quote empty values, addresses, secrets and DSNs. `.yaml` and `.yml` are supported; the default filename is `config.yaml`.
- Startup files use YAML only and have a 64 KiB limit. Restore creates a private `*.secrets.yaml` file.
- Relative upload paths are resolved against the working directory, including when `--config` selects a file elsewhere.
- Docker Compose reads `.env` to interpolate the included Compose template. This is separate from the executable's configuration loader.

A public template is provided at [config.example.yaml](../config.example.yaml). Prefer `launch init`, which generates a valid master key automatically and refuses to overwrite an existing YAML configuration. The completed `config.yaml` is ignored by Git and excluded from the Docker build context. Keep it private and retain it between upgrades.

```yaml
environment: development
http_addr: "127.0.0.1:18080"
https_addr: ""
public_url: "http://localhost:18080"
database_dsn: "launch:YOUR_DATABASE_PASSWORD@tcp(127.0.0.1:3306)/launch?parseTime=true&loc=UTC&charset=utf8mb4"
master_key: "KEEP_THE_KEY_GENERATED_BY_LAUNCH_INIT"
upload_dir: ".local/uploads"
admin_email: ""
admin_password: ""
```

`config.yaml` is private server configuration. It is different from the public `launch-config.json` exported by the application integration wizard; never ship the server configuration with a customer application.

## Server variables

| YAML key | Environment override | Built-in default | Purpose |
| --- | --- | --- | --- |
| `environment` | `LAUNCH_ENV` | `development` | `development`, `test`, or `production` |
| `http_addr` | `LAUNCH_HTTP_ADDR` | `127.0.0.1:8080` | HTTP listener, in `host:port` form |
| `https_addr` | `LAUNCH_HTTPS_ADDR` | Empty | Optional separate HTTPS listener |
| `public_url` | `LAUNCH_PUBLIC_URL` | `http://localhost:8080` | Public HTTP(S) origin; no credentials, path, query, or fragment |
| `database_dsn` | `LAUNCH_DATABASE_DSN` | Empty | MySQL driver DSN; a database name is required |
| `master_key` | `LAUNCH_MASTER_KEY` | Empty | Base64-encoded 32-byte secret encryption key, generated by `init` or `keygen` |
| `admin_email` | `LAUNCH_ADMIN_EMAIL` | `admin@example.com` | Initial administrator email; used only for an uninitialized database |
| `admin_password` | `LAUNCH_ADMIN_PASSWORD` | `LaunchAdmin123!` | Initial administrator password; must be changed after first sign-in; used only for an uninitialized database |
| `upload_dir` | `LAUNCH_UPLOAD_DIR` | `.local/uploads` | Persistent installer and product-document image storage; resolved to an absolute path |
| `backup_passphrase` | `LAUNCH_BACKUP_PASSPHRASE` | Empty | Separate 16-256 character backup/restore passphrase |
| Command option `--config` | `LAUNCH_CONFIG_FILE` | Auto-discover as above | Private YAML file |

`launch init` writes listener/public URL port **18080** explicitly. The built-in port **8080** applies when those values are absent.

When a database is configured, a master key is required. Production additionally requires a database and an HTTPS public URL. Passing configuration validation alone does not enable live sales.

## MySQL DSN

```text
launch:YOUR_DATABASE_PASSWORD@tcp(127.0.0.1:3306)/launch?parseTime=true&loc=UTC&charset=utf8mb4
```

The configuration templates and `launch init` explicitly include `parseTime=true`, `loc=UTC`, and `charset=utf8mb4`. Launch also enforces these settings in the connection code and sets the MySQL session `time_zone='+00:00'`, so existing parameter-free DSNs remain compatible. Conflicting time/charset values such as `loc=Local` are overridden. Display local time at the application/UI boundary rather than storing server-local timestamps. A DSN `loc` value describes how the Go driver interprets time; it does not itself set the MySQL session time zone.

Create the database and account separately. Go/GORM creates and maintains application tables at startup with `utf8mb4` and `utf8mb4_bin`. The driver disables multi-statements and sets bounded connection/read/write timeouts. A database user needs permissions appropriate for GORM schema creation and updates; isolate the application from unrelated databases.

## Private local configuration

```powershell
./bin/launch.exe init
```

Edit `database_dsn` in the generated `config.yaml`, then run `./bin/launch.exe serve`. The master key is generated automatically. Alternatively copy the public YAML example and supply one generated master key with `keygen`.

All server commands select the same file automatically. To select an explicit configuration:

```powershell
./bin/launch.exe check --config ./config.yaml
```

No setup token is needed. On a fresh database, sign in as `admin@example.com` / `LaunchAdmin123!` and complete the required password change. Optional initial-account overrides do not reset an existing installation. Preserve the master key across restarts; replacing it makes stored credentials unreadable.

## External services

Licentivo, Stripe, PayPal, Waffo, Paddle, optional Resend/generic SMTP, and DeepL settings are managed through authenticated administration pages and stored in MySQL. Secrets are encrypted with the instance master key and are not returned by normal configuration reads. They are not frontend environment variables.

See [external-services.md](external-services.md), [payments.md](payments.md), [resend-email.md](resend-email.md), and [multilingual-deepl.md](multilingual-deepl.md).

## Docker Compose variables

The template interpolates `MYSQL_DATABASE` (default `launch`), `MYSQL_USER` (default `launch`), `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `LAUNCH_MASTER_KEY`, optional `LAUNCH_ADMIN_EMAIL`/`LAUNCH_ADMIN_PASSWORD`, `LAUNCH_ENV`, and `LAUNCH_PUBLIC_URL`. MySQL passwords and the master key must be supplied. See [.env.example](../.env.example).

The database is not published on a host port. The application is published on loopback port 8080. The template currently uses a read-only application filesystem; configure a persistent writable upload mount and matching `LAUNCH_UPLOAD_DIR` before accepting file uploads. See the [installation guide](installation.md#docker-compose-development-template).

## Test configuration

`LAUNCH_TEST_DATABASE_DSN`, `LAUNCH_TEST_APP_DATABASE_DSN`, `LAUNCH_TEST_RESTORE_DATABASE_DSN`, and `LAUNCH_TEST_BOOTSTRAP_DATABASE_DSN`, and `LAUNCH_TEST_PROVIDER_DATABASE_DSN` are for isolated integration tests. Use new databases with the required `launch_test_` prefix. Do not use normal development or customer databases. `scripts/test-mysql.ps1` creates its own temporary databases and credentials.

Mail settings store two independent preferences: `require_verification` and `order_notifications`. Both default to true when email is configured. Disabling delivery always allows direct registration and purchase. Disabling verification alone leaves password recovery, confirmed email changes, and other selected notifications available. See [email setup and triggers](resend-email.md).
