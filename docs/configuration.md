# Configuration reference

Launch accepts process environment variables and an optional JSON object of string values. The executable does not automatically load `.env`.

## Loading configuration

- `launch dev` selects `.local/dev/launch-config.json` if `LAUNCH_CONFIG_FILE` is not already set.
- Other commands read a JSON file only when `LAUNCH_CONFIG_FILE` points to it.
- Nonempty process environment values override values in the JSON file.
- JSON files may only contain `LAUNCH_` keys and cannot contain `LAUNCH_CONFIG_FILE` itself. The file size limit is 64 KiB.
- Docker Compose reads `.env` to interpolate the included Compose template. This is separate from the executable's configuration loader.

A safe, unpopulated template is provided at [config/launch-config.example.json](../config/launch-config.example.json). Copy it to an ignored private location and replace all placeholders. Never commit the completed file.

## Server variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `LAUNCH_ENV` | `development` | `development`, `test`, or `production` |
| `LAUNCH_HTTP_ADDR` | `127.0.0.1:8080` | HTTP listener, in `host:port` form |
| `LAUNCH_HTTPS_ADDR` | Empty | Optional separate HTTPS listener |
| `LAUNCH_PUBLIC_URL` | `http://localhost:8080` | Public HTTP(S) origin; no credentials, path, query, or fragment |
| `LAUNCH_DATABASE_DSN` | Empty | MySQL driver DSN; a database name is required |
| `LAUNCH_MASTER_KEY` | Empty | Base64-encoded 32-byte secret encryption key, generated by `launch keygen` |
| `LAUNCH_SETUP_TOKEN` | Empty | One-time administrator setup token; 32-256 characters when configured |
| `LAUNCH_UPLOAD_DIR` | `.local/uploads` | Persistent installer and product-document image storage; resolved to an absolute path |
| `LAUNCH_CONFIG_FILE` | Empty | Private JSON configuration file, selected through the process environment |
| `LAUNCH_BACKUP_PASSPHRASE` | Empty | Separate 16-256 character backup/restore passphrase; keep it outside source control |

When a database is configured, a master key is required. Production additionally requires a database and an HTTPS public URL. Passing configuration validation alone does not enable live sales.

## MySQL DSN

```text
launch:YOUR_DATABASE_PASSWORD@tcp(127.0.0.1:3306)/launch
```

Create the database and account separately. Go/GORM creates and maintains application tables at startup. The driver uses UTC timestamps, disables multi-statements, and sets bounded connection/read/write timeouts. A database user needs permissions appropriate for GORM schema creation and updates; isolate the application from unrelated databases.

## Private local configuration

```powershell
New-Item -ItemType Directory -Path .local/dev -Force | Out-Null
Copy-Item config/launch-config.example.json .local/dev/launch-config.json
./bin/launch.exe keygen
./bin/launch.exe keygen
```

Edit the copied file with your database settings and two separate generated values for `LAUNCH_MASTER_KEY` and `LAUNCH_SETUP_TOKEN`. Then run `./bin/launch.exe dev`.

For commands other than `dev`:

```powershell
$env:LAUNCH_CONFIG_FILE = (Resolve-Path .local/dev/launch-config.json).Path
./bin/launch.exe check
```

Remove the setup token after administrator creation. Preserve the master key across restarts; replacing it makes stored credentials unreadable.

## External services

Licentivo, Stripe, PayPal, Resend, and DeepL settings are managed through authenticated administration pages and stored in MySQL. Secrets are encrypted with the instance master key and are not returned by normal configuration reads. They are not frontend environment variables.

See [external-services.md](external-services.md), [payments.md](payments.md), [resend-email.md](resend-email.md), and [multilingual-deepl.md](multilingual-deepl.md).

## Docker Compose variables

The template interpolates `MYSQL_DATABASE` (default `launch`), `MYSQL_USER` (default `launch`), `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `LAUNCH_MASTER_KEY`, optional `LAUNCH_SETUP_TOKEN`, `LAUNCH_ENV`, and `LAUNCH_PUBLIC_URL`. MySQL passwords and the master key must be supplied. See [.env.example](../.env.example).

The database is not published on a host port. The application is published on loopback port 8080. The template currently uses a read-only application filesystem; configure a persistent writable upload mount and matching `LAUNCH_UPLOAD_DIR` before accepting file uploads. See the [installation guide](installation.md#docker-compose-development-template).

## Test configuration

`LAUNCH_TEST_DATABASE_DSN`, `LAUNCH_TEST_APP_DATABASE_DSN`, and `LAUNCH_TEST_RESTORE_DATABASE_DSN` are for isolated integration tests. Use new databases with the required `launch_test_` prefix. Do not use normal development or customer databases. `scripts/test-mysql.ps1` creates its own temporary databases and credentials.
