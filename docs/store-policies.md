# 商店条款与政策

管理员在「系统设置 → 条款与政策」分别编辑服务条款、退款政策和隐私告知。

- 「保存草稿」只更新后台内容，客户继续看到上次发布的版本。
- 「预览」显示当前编辑内容，不会保存或发布。
- 「发布更新」同时保存并发布当前内容。已发布政策自动进入商店页脚、结账页及产品文档入口。
- 保存或发布请求发出后仍可继续编辑。请求完成时会保留新输入，并提示这些修改尚未保存或发布；下一次保存使用更新后的版本。
- 三份文档独立保存。标题最多 160 字，正文最多 16000 字；空正文可以保存草稿，不能发布。
- 两位管理员同时编辑同一文档时，旧版本会提示冲突。请先复制当前内容，再刷新获取最新版本。

编辑器支持标题、加粗、列表、链接和撤销。正文使用有限 Markdown 格式保存；原始 HTML 作为文字显示，链接限制为 HTTP、HTTPS 或站内地址。

初始正文为空，需要管理员填写。某份全店政策尚未发布时，商品原有的对应政策内容继续生效；发布该全店政策后，公开入口统一使用全店版本。未发布且没有原有商品内容的政策不生成公开链接。

客户访问地址为 `#/policies/terms`、`#/policies/refunds`、`#/policies/privacy`。未发布的文档不可公开读取。管理员身份、账号中心、查看商店和退出登录合并在后台右上角的账号菜单中。

## API

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/admin/policies` | 管理员读取三份草稿及发布状态 |
| PUT | `/api/v1/admin/policies/{key}` | 保存草稿 |
| POST | `/api/v1/admin/policies/{key}/publish` | 保存并发布 |
| GET | `/api/v1/policies/{key}` | 只读取已发布版本 |

`key` 为 `terms`、`refunds` 或 `privacy`。保存与发布传入 `title`、`body` 和当前草稿 `version`；首次保存使用 `0`。过期版本返回 HTTP 409 / `POLICY_VERSION_CONFLICT`，保留已发布内容。后台写操作沿用网站会话、Origin 和 CSRF 校验。

`GET /api/v1/site` 的 `policies` 字段只包含已发布的内容、版本及发布时间。草稿不进入公共接口。政策存储在实例设置中，随现有数据库备份和恢复流程保留。

## 浏览器回归检查

通过本机 HTTP 静态服务提供仓库根目录，打开 `/scripts/store-policies.browser.html` 可运行六项真实 DOM 回归。用例使用受控的异步 API，检查保存期间继续输入、版本更新、未保存提示的比较基准、页面移除后的过期响应、发布后的刷新失败及保存重试，不会连接业务数据库或发布真实政策。
