## 退款授权回退

`internal/app/purchase_sync.go` 不再比较应用生成的 `voided_at` 与数据库生成的 `created_at`。退款/拒付事实和对应的最终快照在同一事务提交；现在用同一授权内的单调版本，识别该已作废订单的最新快照，允许它越过旧的延迟任务。

原始正向购买快照仍须等待，未完成的旧许可证迁移仍不能被越过。最新退款快照确认应用后，旧任务才按原有流程标记为已被替代。使用的是现有订单、覆盖和版本数据，不需要新增数据库列，也不需要改写旧队列的时间戳。

回归覆盖了升级、续费、缺少原正向任务订单关联的历史记录，以及旧队列创建时间落后 1 小时的场景；还覆盖了原正向任务时间领先 1 小时、退款快照已接收但尚未应用时，旧正向任务仍不得发出。

## 安全邮件链接

`internal/app/accounts.go` 为新安全邮件在加密队列载荷中保存凭证 ID，`internal/app/mail_credentials.go` 在每次发送和重试前检查凭证及账号状态。

- 已过期、已使用、被新申请替代或收件账号已不可用的邮件会取消，不占用 SMTP 发送额度，也不会标记为发送成功。
- 取消后清除队列中的加密正文，保留取消原因。
- 旧版已排队、没有凭证 ID 的邮件，通过原邮件链接的凭证摘要兼容校验。
- 有效的注册验证、密码重置和修改邮箱确认仍按原流程发送；不会重新生成凭证或延长原有效期。

新测试验证了当前/旧版载荷的额度等待后过期、重复申请替代、已消费链接的重试，以及有效验证和修改邮箱。原有 HTTP 集成测试改用新申请的有效链接验证 SMTP 失败重试，同时明确断言旧的已消费链接被取消。
