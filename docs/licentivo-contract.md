# Licentivo management API integration

The adapter implements the existing Licentivo management API. Launch does not depend on a separate licensing sandbox, a new sales API, or a replacement runtime SDK.

## Administrator configuration

1. Create products and licensing policies in Licentivo.
2. Create a management key (`lv_api_...`) with **read/write** access. A read-only key can read products but cannot issue licenses after customer payment.
3. Enter the key in **System settings > Licentivo connection**. The origin is fixed to `https://www.licentivo.com`.
4. Select a Licentivo policy by name when creating/editing a sales plan. Launch discovers the associated product and saves the policy version and full licensing parameters with the plan version.

There is one connection per Launch instance. Test and live orders share it; only Stripe/PayPal payment credentials are split by payment environment. The key is encrypted on the Launch server and never included in static files, customer applications, or public SDK configuration.

## Existing endpoints used by Launch

| Endpoint | Purpose |
| --- | --- |
| `GET /api/v1/products` | Read products |
| `GET /api/v1/policies`, `GET /api/v1/policies/{id}` | Read and verify policies and versions |
| `POST /api/v1/licenses/batch` | Idempotent issuance, renewal, and policy application |
| `POST /api/v1/licenses/policy-preview` | Check policy changes and device conflicts before upgrade |
| `GET /api/v1/licenses/{id}` | Reconcile license identity, policy, and state |
| `PATCH /api/v1/licenses/{id}` | Set active/suspended state |
| `GET /api/v1/activations` | Read customer devices |
| `POST /api/v1/activations/{id}/release` | Release a device |

Requests use `Authorization: Bearer lv_api_...`. Customer passwords, order amounts, and payment credentials are not sent to Licentivo. The license customer field uses a random opaque reference generated by Launch.

## Issuance after payment

Launch verifies the provider result, records immutable order coverage, and creates a licensing task in a local transaction. A worker then calls Licentivo:

1. Initial purchase uses the batch `create` operation.
2. The full license key is returned with the original creation result. Launch immediately encrypts it and only supplies it through the authenticated software API to the owning account.
3. Renewal uses `renew`; upgrade performs `policy-preview` followed by `apply_policy`.
4. Refunds, account disablement, and expiration of local paid coverage suspend the remote license. Permanent revocation is a distinct terminal administrator action.

Every remote step uses a stable `request_id` derived from the local task UUID. Licentivo retains batch results, so a connection loss after commit can be recovered with the same request and original one-time key, rather than issuing another license. Policy retries read the current license first and complete locally if the intended policy is already applied.

## Validity and state limitations

Licentivo's term policy can start at first successful activation, whereas Launch calculates sales coverage from verified payment. The adapter ensures enough remote days for the remaining paid coverage and suspends the license when the local contract expires.

**Launch background workers must keep running.** A long outage at the expiration boundary can delay remote suspension until the service recovers. The local ledger retains orders, refunds, and intended state for later reconciliation. An upstream absolute-validity API could improve this without changing the order ledger; it is not assumed to exist today.

Licentivo remains authoritative for runtime device limits, features, heartbeats, and offline rules. Launch plans define names, prices, sales terms, and presentation. Policy selection verifies product, policy ID, and version; changing an upstream policy requires a new or remapped Launch plan version.

## Customer application integration

Applications use the official Licentivo SDK with the public product configuration and keys. After merchant-account login, Launch's software endpoint returns the current account's own product credential. See [software-sdk-integration.md](software-sdk-integration.md).
