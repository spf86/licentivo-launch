# 订单管理

后台「订单」可按订单编号、客户邮箱或产品名称搜索完整历史记录，并按状态、正式/测试环境、待核对情况筛选。默认每页 25 笔；创建时间相同的订单以编号排序，翻页顺序保持稳定。

状态同时显示文字和颜色：已付款为绿色，等待付款和退款中为橙色，已退款为蓝色，已撤款为红色，已关闭为灰色。颜色不随品牌主题改变。

管理员和运营可使用订单行内的「核对付款」，也可跨页选择最多 25 笔订单后核对。每批最多处理 5 笔，界面显示进度与逐笔结果。部分订单失败不会阻止同批其他订单；连接中断时不会自动重复请求，后续批次停止，需查看最新状态后继续。核对原因写入操作记录。客服只能查看订单。

核对会沿用原有的支付恢复逻辑，包括适用时恢复原结账或确认原交易；它不直接把订单改为已付款。实际支付渠道的行为仍需配置对应凭据后验收。

手工发票申请和后台处理表单已移除，对应两个写入接口返回 `410 INVOICE_REQUESTS_DISABLED`。历史发票记录和只读查询保留，不删除已有数据。此变更不会自动生成商业发票、计算税款或接入新的支付服务。

管理接口：

- `GET /api/v1/admin/orders/search`：`q`、`status`、`environment`、`needs_review`、`limit`（1–100，默认 25）、`offset`（默认 0）。返回 `items`、`total`、`limit`、`offset`。
- `POST /api/v1/admin/orders/reconcile`：`order_ids`（1–5 个不同编号）和 `reason`（2–500 字符）。返回每笔订单的 `order_id`、`checked`、`message` 及失败时的 `code`。`checked` 表示核对请求完成，订单是否已付款应以刷新后的订单状态为准。
- 既有 `GET /api/v1/admin/orders` 和单笔核对接口保持兼容。
