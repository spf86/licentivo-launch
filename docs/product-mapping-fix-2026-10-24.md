# Launch 套餐产品映射并发修复

已修复授权审查中的 AUTH-03。仅修改 Launch 服务端与对应回归测试，未部署、未发布 SDK；Licentivo 和 SDK 的授权决定边界不变。

## 修改

- 保存映射时，在事务内先锁定共同的 Launch 产品记录，再锁套餐版本。不同套餐或不同进程的保存请求因此遵守同一产品锁；冲突请求返回 HTTP 409 `PRODUCT_MAPPING_CONFLICT`。
- `products.licentivo_product_id` 保存稳定的公开产品路由。首次成功保存映射后，同一 Launch 产品的其他套餐只能选择这个 Licentivo 产品；允许选择其不同策略。该字段不保存功能权限、设备额度或客户授权状态。
- 客户身份读取稳定路由，不再根据所有套餐的最大版本选择产品。发布套餐及生成 SDK 接入配置时也核对同一绑定。
- 旧库自动增加可空字段。尚无稳定字段的数据依次参考已付款等购买历史、历史发布记录和其余映射；同一优先级存在多个产品时明确提示冲突，不猜测。唯一的已购产品优先于无关草稿，之后保存兼容映射可固化绑定。产品内容编辑保留绑定。

已经售往多个 Licentivo 产品的历史错误数据仍需人工核对，本次不会改写购买记录或远端许可证。需要改用另一个 Licentivo 产品时，应建立新的 Launch 产品，不能借新套餐改写原产品路由。

实现见 [映射保存](../internal/app/connections.go)、[产品路由](../internal/app/product_mapping.go)、[身份签发](../internal/app/identity.go)、[发布校验](../internal/app/catalog.go)、[接入检查](../internal/app/integration.go)、[数据模型](../internal/storage/models.go)。
