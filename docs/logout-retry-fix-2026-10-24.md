# Launch SDK 账号退出重试修复

日期：2026-10-24。已修复 AUTH-07，并同步 Go、JavaScript、Python、C#、Java、Ruby、Rust、C、C++ 的账号生命周期入口。**未部署、未发布 SDK、未提交或推送 Git。** 本任务没有修改 Launch 或 Licentivo 服务端业务代码。

## 行为

显式退出先将安全存储中的账号记录标记为“仅待撤销”，再调用官方 SDK 退出并向 Launch 提交账号会话撤销。无论网络或取消状态如何，本地运行时都会停止，不允许继续执行受保护功能。

Launch 未确认撤销时，SDK 保留待办及重试所需的原账号凭据，不再把它当作已登录账号。再次 `Logout`、`Login` 或 `Restore` 会恢复撤销请求；`Restore` 不会拿待办请求身份或启动授权运行时。收到成功响应，或收到表明原会话已不能认证的 HTTP 401 后，才删除账号待办。因此响应丢失也能恢复，不会出现“第二次退出返回成功，但从未补交撤销”的情况。

正常已登录记录仍兼容 v2。待撤销记录使用私有 v3 格式；Java、Rust 还移除了正常登录所需的凭据字段形状，避免旧版 SDK 将待办误当成正常登录。待办不保存短期身份断言、许可证密钥或签名许可。

账号待办使用原来配置的安全 `Store`。**跨进程恢复需要持久化安全存储**，例如 Windows DPAPI 或 SDK 支持的加密存储；默认 `MemoryStore` 只在本进程保留数据。重试由后续登录、恢复或退出操作触发，没有新增独立后台任务。存储或撤销未完成会返回错误或待完成结果，不提示成功。

Licentivo SDK 的设备退出票据和 `.logout.json` 仍由它管理，Launch 不删除其缓存目录，不判断设备、功能或离线权限。同步更新了原生示例和各语言 SDK 文档。

## 两端联调

使用本机独立 MySQL 8.0.32、当前 Launch、Licentivo 服务及其工作进程、实际 Go Launch SDK 与官方授权运行时、DPAPI 账号存储，完成 **15 个业务阶段**。

新增两种退出故障验证：

1. **请求未送达 Launch**：账号退出接口暂时返回 503。SDK 停止本地功能，真实 Licentivo 设备绑定释放，账号撤销待办保留。重建 SDK 后仍只重试退出；恢复连接后，原 Launch 会话被撤销，Licentivo 确认收到对应会话通知。
2. **服务端已撤销，但回包丢失**：Launch 已处理退出，测试代理将响应替换为 503。待办跨 SDK 重建保留；恢复连接后，通过 HTTP 401 确认原会话失效并删除待办。过程中没有恢复登录或重新激活设备。

其余阶段覆盖实际购买同步与签名功能运行、普通关闭恢复、正常退出、远程解绑及旧代次、续费退款、账号撤销与重新登录、全额退款拒绝运行、退款恢复、拒付和大文档翻译回归。Licentivo 三项更新由其负责方提供，本任务只构建和验证。

支付渠道和 DeepL 使用隔离模拟服务，没有真实扣款、退款或付费翻译。真实联合服务验证使用 Go；其他语言完成本地 SDK 回归，不声称九种语言分别完成了一套真实服务部署验收。
