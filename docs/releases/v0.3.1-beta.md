# Licentivo Launch 0.3.1-beta

This beta updates the merchant server, client integrations and purchase-to-license reconciliation.

- Deliver restrictive entitlement updates independently of unresolved positive synchronization, with explicit downgrade snapshots for the matching Licentivo server.
- Correct renewal recovery, full-coverage upgrade quotes, refunds, reversals, plan mapping and affected purchase synchronization paths.
- Add durable login-session revocation delivery and strengthen account, product and environment boundaries.
- Improve large translation batches and external-provider error handling.
- Update the nine-language Launch SDK integration to 0.1.3 with reviewed Licentivo SDK 0.11.2, including logout persistence, stale-instance cache isolation and old-login binding protection.

Release artifacts contain Windows and Linux builds for amd64 and arm64, installation instructions, source archives and SHA-256 checksums. Existing configuration, master keys, uploads and MySQL data must be preserved when upgrading.

## Installation and first login

1. Prepare MySQL 8.0.16+, an empty database, and a dedicated database user. Download the package for the server's operating system and architecture from [this release](https://github.com/spf86/licentivo-launch/releases/tag/v0.3.1-beta), extract it, and open a terminal in the extracted directory.
2. Run `.\launch.exe init` on Windows or `./launch init` on Linux. This writes `config.yaml` and a persistent master key; it does not create an administrator or start MySQL.
3. Edit `database_dsn` in `config.yaml` and retain the generated `master_key`. To choose your own initial account, set `admin_email` and `admin_password` before the first server start. Nonempty `LAUNCH_ADMIN_EMAIL` / `LAUNCH_ADMIN_PASSWORD` process variables override the corresponding YAML values.
4. Run `.\launch.exe serve` or `./launch serve`. The first start against an uninitialized database creates one administrator and prints the selected credentials in the server terminal.
5. With the generated configuration, open `http://localhost:18080/#/login` in a browser on the server. **Only when no initial-account overrides were supplied**, sign in as `admin@example.com` with initial password `LaunchAdmin123!`; otherwise use your configured credentials.
6. Enter a different password of 12-128 bytes in the required first-login form, save, and sign in again. This is required even for custom initial passwords. Administration and desktop sessions remain blocked until the change is complete. Complete this step before exposing the public site.

The built-in initial password is fixed, not randomly generated; the generated master key is a separate encryption secret. Initial-account settings are used only for an uninitialized database. Changing them, restarting, or upgrading does not reset an existing account or password. Subsequent starts use `serve` directly; `init` refuses to overwrite an existing configuration.

The generated configuration uses port **18080**. Omitted listener/public URL values and the development Compose template use **8080**. The generated listener is loopback-only; for a browser on another computer, use the [remote first-login instructions](https://github.com/spf86/licentivo-launch/blob/main/docs/installation.md#first-login-on-a-remote-server).

See the [binary installation guide and checksums](https://github.com/spf86/licentivo-launch/blob/main/docs/binary-installation.md), [configuration reference](https://github.com/spf86/licentivo-launch/blob/main/docs/configuration.md#initial-administrator-credentials), and [login troubleshooting](https://github.com/spf86/licentivo-launch/blob/main/docs/installation.md#health-and-troubleshooting).

Licentivo remains the authority for device bindings, features, limits, signed grants and runtime verification. This beta does not replace deployment-specific payment, email and production acceptance checks.
