# Licentivo Launch 0.3.2-beta

This release adds a custom HTTP licensing provider alongside the existing Licentivo integration. Choose one provider for the store in **System settings → Licensing system**, then configure product and environment mappings before publishing plans.

- Connect an existing licensing service through the signed `launch-external-licensing-v1` protocol: capabilities, versioned entitlement snapshots, durable event receipts, and customer delivery queries.
- Protect connections with per-environment HMAC-SHA256 credentials, timestamp and nonce checks, pinned delivery origins, bounded requests, and encrypted server-side secret storage.
- Recover interrupted synchronization by querying the original event before resubmitting the same event ID and exact payload. Older versions cannot replace newer commercial state.
- Recompute remaining purchase coverage after renewals, upgrades, refunds, reversals, suspension, and expiry. A receipt confirms synchronization; the merchant's own SDK still decides runtime authorization.
- Publish the protocol and integration guide from each Launch server at `/api/v1/licensing/protocol` and `/api/v1/licensing/documentation`. A Python adapter example is included in the source archive.
- Update installation guidance to Launch Client SDK 0.1.4, with the pinned Licentivo SDK 0.11.2 runtime included. Custom-provider products use the merchant's own licensing SDK.

Download the package matching Windows or Linux and amd64 or arm64. Verify it against `SHA256SUMS.txt`. To upgrade, back up the database and preserve the existing configuration, master key, uploads and application data before replacing the executable. Run `serve` using the existing configuration; do not rerun `init`.

New installations use `launch init`, edit `database_dsn`, then run `launch serve`. The generated listener is `http://localhost:18080`. The first administrator must complete the mandatory password change before deployment is exposed publicly. See [installation](../installation.md) and [configuration](../configuration.md).

The [custom licensing guide](../external-licensing.md), [protocol OpenAPI](../external-licensing-openapi.json), and [adapter example](../../examples/custom-licensing/README.md) describe the receiver contract and acceptance flow. Payment processing, email delivery and the merchant's own licensing service require deployment-specific sandbox verification.
