# Launch SDK 0.1.2 publication

Release: [Launch SDK v0.1.2](https://github.com/spf86/licentivo-launch-sdk/releases/tag/v0.1.2), source commit `ac983627784de4ca38c2e71e85b60526bb046251`.

Status: **9/9 public installation checks passed**. Go Modules, PyPI, NuGet, Maven Central, npm, crates.io and RubyGems are published and verified. C and C++ downloads are published on GitHub Releases and verified against relocated Windows amd64 GNU installations. Every language's documented public installation method is available and verified.

Maven Central deployment `cac96184-c336-4799-a759-9d59a73d3d95` is publicly available. The JAR and POM match the reviewed GitHub artifacts. Detached signatures for the JAR, POM, sources and Javadoc verified against release key `C3332760927486E96AB75E753619EE6EFA7EC061`; the public version index includes 0.1.2. An independent JDK 17 consumer compiled and executed the actual generated Java connection function.

Each 0.1.2 package embeds official Licentivo SDK 0.11.1 and the default Launch adapter. SDK 0.11.1 fixes C/C++ CMake consumption across curl config-package and FindCURL discovery modes by resolving the installed dependency through `CURL::libcurl`. Applications do not need to add compatibility aliases. Matching compiler, architecture and curl runtime/development dependencies remain required.

The licensing protocol and client API are unchanged. The other language packages share the new version and retain their existing behavior. Update the Launch package to 0.1.2 and rebuild; no separate official SDK installation or changes to account login, restore or feature guards are required.

Every passed language was installed in an independent consumer and executed the actual initialization code generated by the Launch backend. Python installed its ordinary dependencies in a new virtual environment. npm passed strict TypeScript compilation. NuGet adds a repository signature; all nine original package payload files match the reviewed GitHub artifact. Ruby's platform gem matches the release checksum and requires no official SDK gem. Rust was installed from the exact crates.io version in an isolated Cargo home without a local path or replacement; its crate matches the release checksum and its generated initialization passed.

Go used the standard `https://proxy.golang.org,direct` setting, no local replacement and the public checksum database; `go mod verify` passed. A transient proxy-side GitHub DNS error affected the `.info` endpoint, while `.mod` and `.zip` downloaded from the public proxy. The failed attempt and successful fallback evidence are retained separately.

Independent C and C++ consumers compiled and ran against the downloaded, relocated native package using both default curl discovery and `CURL_NO_CURL_CMAKE=TRUE`. The exact Launch 0.1.2 and upstream 0.11.1 package versions were required. The generated C/C++ initialization snippets also passed in both modes. These public consumer checks were performed on Windows amd64 with GNU/MinGW; they do not claim macOS or ARM64 execution.

The detailed maintainer evidence is retained in `artifacts/sdk-012-public-summary.json` and its per-language paths in the Launch workspace. These local paths are not public download links. The original [0.1.1 publication](publication-0.1.1.md), [status](registry-status-0.1.1.json) and [verification receipt](registry-verification-0.1.1.json) remain archived with their original results.
